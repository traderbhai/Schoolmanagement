# Admission KPI Drilldown Audit

Scope: `/admission/dashboard`, lead/applicant/document/payment/enrollment drilldowns, Admission command center, and Admission sidebar manifest.

## Verified Issues

| Surface | Issue | Impact | Fix |
| --- | --- | --- | --- |
| Admission dashboard funnel | `Enrolled` used `Student::count()` instead of completed admission enrollments. | Dashboard could show every student in the institute as Admission enrolled, while clicking showed only admission confirmations. | Added `AdmissionKpiDrilldownService::completedEnrollmentQuery()` and wired dashboard enrolled count to completed `EnrollmentConfirmation` rows in the user's Admission scope. |
| Admission dashboard cards | Dashboard used unscoped global `Applicant`, `Lead`, `ApplicantDocument`, and `AdmissionPayment` counts. | Scoped users could see counts that did not match the records they are allowed to open. | Dashboard now uses shared scoped queries from `AdmissionKpiDrilldownService`. |
| Pending documents | Document queue list was scoped/filtered, but top stats used global pending/verified/rejected document counts. | A pending document card could show a higher number than the queue after click. | Pending stat now uses the same filtered query as the queue; all-visible pending total remains available as context. |
| Pending payments | Payment queue already scoped pending rows but verified-today stats were global. | Queue context could mix visible pending rows with global operational stats. | Payment queue verified-today and all-pending context are now scoped through the shared drilldown service. |
| Destination pages | Applicant, lead, document, payment, and enrollment pages showed totals but not the filter meaning behind drilldowns. | Users could not tell why a clicked KPI opened a specific set of records. | Added visible filter summaries to the affected list pages. |
| Admission command center | Command center uses `AdmissionKpiService`, which applies lead/applicant visibility before computing KPIs. | No direct mismatch found in the current command center KPI source during this slice. | No code change required in command center for this audit slice. |
| Admission sidebar | Current `FrontendNavigation` Admission entries do not define live badge count fields. | The reported sidebar number is not generated by the canonical sidebar manifest in current code. | No sidebar badge patch required; future live badges should consume `AdmissionKpiDrilldownService` rather than ad hoc counts. |

## Regression Contract

- Dashboard KPI/card values must be computed from the same scoped query families used by destination pages.
- Any dashboard number that links to a list must either:
  - link to a page whose total equals that KPI, or
  - show a clear filtered total and context if extra filters are applied.
- Enrollment KPIs must count completed admission enrollments, not all institute students.
- Pending document and payment queue stats must respect Admission hierarchy visibility.
- Future sidebar badges for Admission must use `AdmissionKpiDrilldownService` or another shared source-backed service.
