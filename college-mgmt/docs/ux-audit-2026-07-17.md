## Fixes Completed During Audit

### 1. Role dashboard navigation

Problem: the shared profile/navigation layout sent many non-student roles to `/student/dashboard`, creating visible 403 links.

Fix:

- Added `DashboardRedirect::routeNameForUser()`.
- Updated `resources/views/layouts/navigation.blade.php` to use the central role dashboard mapping.

Impact: Dean, PMC, Admission, Accounts, Exam Cell, CMC, Teacher, Applicant, Parent, and Admin users now get the correct dashboard destination from shared navigation.

### 2. Admission reminder scope links

Problem: Admission reminder rows could show applicant links outside the viewer's actual admission hierarchy scope.

Fix:

- Hardened `AdmissionReminderService::queryFor()` to require both reminder ownership/assignment visibility and subject visibility.
- Hardened `AdmissionReminderService::canAccess()` to check the linked lead/applicant visibility before allowing reminder actions.

Impact: reminder queues no longer expose dead-end applicant links to scoped admission users.

### 3. Academics governance setup links

Problem: Exam Cell users could see department hierarchy setup links that routed to 403.

Fix:

- Hid generic hierarchy setup actions unless `$canConfigure` is true.
- Added explanatory text for read-only governance users.

Impact: governance remains useful as a read surface without advertising unauthorized setup actions.

### 4. Program Chair curriculum page crash

Problem: `/program-chair/curriculum` could hit a collection/property mismatch and render a service error.

Fix:

- Returned a flat `ProgramSubject` collection from `PmcCurriculumController@index`; the Blade view already handles grouping.

Impact: curriculum manager loads correctly for Program Chair users.

### 5. Academic attention queue detail dead ends

Problem: valid command-center queues such as `pending_approvals` and `draft_timetable` could render as 404 or unknown when accessed from another academic workspace.

Fix:

- Command-center attention detail routes now render the queue page instead of aborting for cross-workspace academic queues.
- `AcademicAttentionService::queue()` resolves queue definitions from the command workspace.

Impact: attention links are stable across Dean/PMC/Exam academic workspaces.

### 6. Student timetable mobile empty state

Problem: the student timetable empty-state alert showed horizontal clipping in narrow mobile capture.

Fix:

- Added page-scoped mobile wrapping and width constraints in `resources/views/student/timetable.blade.php`.

Impact: the empty state is safer for narrow student devices without changing the global portal layout.

### 7. Student mobile priority pages

Problem: several student self-service pages used desktop-first tables or tight action rows that are hard to use on phones.

Fix:

- Added mobile card layouts for Student Dashboard today classes, Student Documents requests, Student Fees demands/structures/payments, and Course Hub action rows.
- Kept desktop tables available on wider screens.

Impact: priority student flows now have phone-friendly card layouts without removing expert desktop density.

### 8. Shared destructive-action context

Problem: shared delete modals warned that an action could not be undone but did not explain likely downstream impact.

Fix:

- Updated Admin and Teacher shared delete modals to call out linked timetable, attendance, finance/admission/materials/report/audit records.
- Added regression coverage so the warning and modal accessibility attributes remain present.

Impact: destructive actions now give users better context before irreversible changes.

### 9. Priority accessible action names

Problem: several improved surfaces rely on card-style or compact actions; those must keep accessible names as the UI becomes denser.

Fix:

- Added regression coverage for accessible labels on Admin, Teacher, Student, PMC official timetable, Student Fees, and Student Dashboard priority actions.

Impact: future UI compaction is less likely to remove keyboard/screen-reader action names from the highest-traffic pages.

### 10. Admission and finance operating density

Problem: Admission Command Center kept daily operating guidance always open, while the Admin Fee Management surface had dense desktop-first controls and icon-only fee actions without accessible action names.

Fix:

- Converted the Admission supervisor control cycle into a collapsible `details` panel with a visible "View cycle" affordance.
- Made Admin Fee Management header actions wrap on smaller screens and wrapped the fee structure table responsively.
- Added accessible names to fee structure view/edit/delete icon actions.
- Normalized fee screen currency/fallback text to avoid mojibake in rendered output.

Impact: Admission supervisors still have the same workflow guidance, but it no longer competes with live queues by default. Finance users get a cleaner mobile-safe fee page and clearer assistive labels.

### 11. Admission payment verification safety copy

Problem: verifying an admission payment used a generic confirmation that did not remind staff to check amount, applicant, bank/gateway reference, and proof.

Fix:

- Updated Admission payment queue and applicant payment verification confirmations to include the amount, applicant context, and reference/proof check.

Impact: staff get a clearer final checkpoint before a payment becomes verified and affects admission readiness.

### 12. High-impact publish and decision confirmations

Problem: timetable publish, merit-list bulk decisions, and offer-letter generation used short generic confirmations despite changing official downstream workflows.

Fix:

- Updated Program Chair timetable publish confirmation to mention conflict audit, selected scope, faculty, rooms, student timetables, attendance, and reports.
- Updated Admission merit-list bulk decision confirmation to mention program/batch/rank scope, offer letters, seat holds, waitlist movement, and enrollment readiness.
- Updated bulk offer-letter generation confirmation to mention merit decisions, seat capacity, payment deadlines, and contact details.

Impact: staff get a clearer final checkpoint before actions that affect official scheduling, admissions decisions, offers, and enrollment readiness.

### 13. Curriculum downstream lock state

Problem: Program Chair curriculum rows warned about downstream impact, but a subject could still be removed after it had entered course-group, enrollment, faculty-assignment, or timetable workflows.

Fix:

- Added a backend curriculum usage guard before `ProgramSubject` deletion.
- Locked removal when the curriculum subject is connected to course groups, faculty assignments, student enrollments, published canonical timetable sessions, or published legacy timetable rows.
- Updated the curriculum table to show a `Locked` badge and `Use curriculum revision` guidance instead of a delete action.

Impact: Program Chairs get a clear read-only state, and protected curriculum rows cannot be deleted through direct requests.

### 14. Timetable lifecycle and hierarchy visibility safety

Problem: PMC freeze/unfreeze/rollback actions had no explicit confirmation, and Admin organization hierarchy toggles/delete actions were icon-only or generic despite changing cross-role visibility.

Fix:

- Added impact confirmations and accessible names to PMC version freeze, unfreeze, and rollback actions.
- Added accessible names and confirmation prompts to Admin organization hierarchy summary/full-access toggles.
- Replaced the generic reporting-line delete prompt with copy that names dashboard visibility and full portal access impact.

Impact: staff get a clear checkpoint before official timetable lifecycle changes and role-visibility changes that affect dashboards and portal access.

### 15. Admission document and refund action confirmations

Problem: document verification and refund lifecycle actions used generic confirmation prompts even though they affect admission readiness, applicant communication, finance audit, and reconciliation.

Fix:

- Updated single and bulk document verification confirmations to mention preview, applicant identity, and admission document policy checks.
- Updated refund approval confirmation to mention verified payment balance, bank details, policy eligibility, and audit notes.
- Updated refund rejection confirmation to mention applicant communication and audit review.
- Updated refund processing confirmation to mention final UTR, completed bank transfer, and finance reconciliation.

Impact: admission and finance staff get concrete last-step checks before document/readiness or refund/reconciliation state changes.

### 16. Finance and admission setup action confirmations

Problem: fee demand generation, late penalties, hostel fee paid/waive actions, application-window deletion, admission setup deletion, applicant document verification, and scholarship cancellation still used generic confirmation prompts despite changing finance balances, applicant readiness, published windows, or audit-sensitive records.

Fix:

- Updated academic fee demand generation confirmation to mention fee structure, due dates, scholarships, active student list, and finance ledger creation.
- Updated late penalty confirmation to mention penalty policy, due dates, waivers, and student balance impact.
- Updated hostel fee paid and waiver confirmations to mention amount, student, receipt/room/month context, reconciliation, waiver authority, audit reason, and NOC/clearance impact.
- Updated admission config delete confirmations for required documents, selection steps, and fee installments to mention applicant readiness, active assessments, merit/evaluator workflow history, offer deadlines, payments, and reconciliation dependencies.
- Updated application window deletion confirmation to mention applicants, published dates, capacity limits, and campaign links.
- Updated applicant document verification and scholarship cancellation confirmations to mention identity/policy checks, fee-demand discount history, applicant communication, and audit reason.
- Added accessible labels to the compact icon buttons introduced or reviewed in these areas.

Impact: staff get clearer final checkpoints before actions that can change official fee balances, admission eligibility, applicant communications, or setup rules used by active workflows.

### 17. Admission assessment, offer, and session operation confirmations

Problem: assessment scheduling, evaluator replacement, GD group building, submission status updates, check-in lifecycle updates, offer round creation/publish, waitlist/seat release/deferral actions, call-letter dispatch, session completion, and candidate removal still used short prompts that did not explain the operational consequences.

Fix:

- Updated assessment slot creation, individual/bulk assignment, evaluator acceptance/replacement, GD group building, submission status updates, and candidate check-in confirmations to mention capacity, scope, evaluator readiness, conflict queues, evidence, and scoring impact.
- Updated offer and seat-control confirmations to mention merit decisions, seat matrix/capacity, payment deadlines, waitlist rules, applicant communication, deferral carry-forward notes, and target batch readiness.
- Updated assessment session confirmations to mention attendance, panel score readiness, unresolved exceptions, call-letter details, notification state, and schedule conflicts.
- Added accessible remove labels for compact candidate removal actions.

Impact: admission staff get clearer checkpoints before changing candidate schedules, seat pressure, official offer state, or assessment communications.

### 18. Lower-frequency operations action confirmations

Problem: library, transport, asset custody, consumable stock, role revocation, academic calendar deletion, and OBE outcome removal actions still used compact generic prompts. These actions are lower-frequency than dashboard/timetable/admission workflows, but they still affect access, custody, inventory, fines, calendars, accreditation evidence, and student services.

Fix:

- Updated asset assignment/return and stock receive/issue confirmations to mention custodian, inspection, accessories, stock quantity, vendor/reference, recipient, purpose, and low-stock impact.
- Updated transport assignment ending confirmation to mention route/stop removal, monthly fee impact, vehicle capacity release, and student communication.
- Updated library issue return, reservation fulfil/cancel, and fine payment confirmations to mention borrower/copy state, queue fairness, fine/receipt status, and shelf availability.
- Updated role revocation confirmations to mention dashboard access, approvals, reports, portal permissions, and scoped program/batch visibility.
- Updated academic calendar deletion confirmation to mention published timetables, holidays, exams, attendance windows, and communication impact.
- Updated OBE CO/PO/PSO removal confirmations to mention OBE mappings, attainment records, assessment rubrics, curriculum reports, specialization evidence, and accreditation submissions.
- Added accessible labels to compact icon-only removal/return/revoke controls reviewed in this pass.

Impact: the remaining operational actions now provide a concrete last-step check before staff change access, inventory, library records, calendar state, or accreditation-linked outcomes.

### 19. Official records, teacher content, hostel movement, and Dean accountability confirmations

Problem: several remaining official-record actions still used short prompts, including admission record deletion, seat matrix deletion, student document request rejection, hostel outpass approval/return, hostel allocation vacation, teacher material/announcement deletion, Program Chair faculty unassignment, and Dean review/planning actions.

Fix:

- Updated admission record deletion confirmations to mention applicant history, enrollment audit, fees, and reports.
- Updated seat matrix deletion confirmation to mention offer rounds, waitlist movement, category allocation, and enrollment reports.
- Updated student document request rejection confirmation to require actionable rejection context for the student.
- Updated hostel outpass approval/return and allocation vacation confirmations to mention policy, active allocation, return evidence, fees, inspection, and bed capacity impact.
- Updated teacher material and announcement deletion confirmations to mention student dependency, class, assessment, timetable, and course-delivery communication.
- Updated Program Chair faculty unassignment confirmation to mention course group coverage, timetable sessions, workload approval, and student communication.
- Updated Dean review/planning confirmations to mention scope, source readiness, owners, priority, due dates, escalation, blockers, evidence, and accountability records.

Impact: staff now get a clearer checkpoint before changing official records, student-visible learning content, hostel movement state, faculty coverage, or Dean accountability workflows.

### 20. Final broad-scan generic confirmation cleanup

Problem: the remaining broad scan still found generic prompts in applicant document removal, bulk mail, legacy timetable deletion, company and placement-drive deletion, scholarship and curriculum decisions, selection-process deletion, specialization removal, CMC drive/event creation, and Program Chair mentor bulk assignment.

Fix:

- Updated applicant document removal to remind applicants to upload the correct replacement before readiness checks.
- Updated bulk email dispatch to mention audience filters, subject/body, contact policy, and dispatch impact.
- Updated legacy timetable entry removal to call out canonical PMC source-of-truth, attendance, teacher/student timetables, and reporting impact.
- Updated company, placement drive, specialization, scholarship, and student-scholarship prompts to mention dependent applications, offers, drives, reports, finance, curriculum, admissions, and student communication.
- Updated curriculum-change approval/rejection prompts to mention timetable, course groups, OBE mapping, faculty load, student communication, and audit-ready rejection reasons.
- Updated admission selection-process step/parameter deletion prompts to mention active assessments, scores, merit calculations, evaluator assignments, rubrics, and historical reports.
- Updated CMC drive/event creation prompts to mention student visibility, communication readiness, eligibility, dates, seats, and registration deadlines.
- Updated Program Chair bulk mentor assignment prompt to mention existing mentor coverage, student support ownership, and mentor reports.

Impact: the broad confirm-text scan is now much closer to the expected UX standard: even one-off actions explain scope and downstream impact instead of using generic "Delete?" or "Remove?" prompts.

### 21. Core admin icon-button accessible names

Problem: several legacy admin list pages used compact icon-only View/Edit/Delete/Approve/Reject actions that relied on visual icons or `title` text. Those are easy for sighted mouse users, but weak for keyboard and screen-reader users.

Fix:

- Added explicit `aria-label` names to compact actions in Academic Years, Courses, Timetable Slots, Teachers, Classrooms, Subjects, Batches, Admissions, Library Books, Grievances, and Leaves.
- The labels include the affected record where available, such as academic year, course, teacher, classroom, batch, admission record, book, grievance, or leave requester.
- Added static regression coverage so these priority admin labels are preserved.
- Re-ran the focused admin scan for `title="View"`, `title="Edit"`, `title="Delete"`, `title="Approve"`, and `title="Reject"`; no matches remain in `resources/views/admin`.

Impact: priority admin list actions are now more understandable to assistive technology and less ambiguous when navigated out of visual context.

## Findings By Area

### P0 - Broken or misleading navigation

Status: fixed for the hard issues found in this audit.

Original examples:

- `/profile` showed `/student/dashboard` for Dean, PMC, Accounts, CMC, and Admission users.
- Admission reminders exposed applicant links that the viewer could not open.
- Exam Cell governance exposed department hierarchy setup links that returned 403.

Recommendation: keep a visible-link crawler in regression checks for each role. This is one of the highest-value UX tests for a role-heavy ERP.

### P1 - Page density and action overload

Affected pages:

- Admin dashboard
- PMC Command OS
- Admission reminders
- Admission Command Center
- Admin Fee Management
- PMC official timetable action bar

Observed issue: many pages are operationally complete but cognitively heavy. Users see setup chips, workflow chips, KPI cards, tables, action buttons, sidebars, and charts at the same time.

Recommended changes:

- Make one primary next action visible per row/card. Partially completed for PMC attention rows and Admission reminders.
- Move secondary actions into compact menus or detail drawers.
- Use progressive disclosure for setup sequences and long operating guidance. Completed for the Admin dashboard setup/operating checklist and Admission Command Center supervisor cycle.
- Add "Today / Needs action / Recently updated" grouping on dashboards.

### P1 - Master timetable discoverability

Affected page: PMC official timetable.

Observed issue: the page successfully shows multiple parallel official sessions in the same slot, which is the right institute model. The session cards still look mostly informational; users need a clearer way to open session detail, conflicts, attendance bridge, substitutions, and change history.

Recommended changes:

- Make every official session card visibly clickable. Completed: PMC official timetable session cards now link to canonical session detail pages.
- Add a compact "Open details" affordance on each card. Completed.
- Keep the parallel slot board as the primary view; avoid returning to a single-session-per-slot model.

### P1 - Mobile student experience

Affected page: student timetable mobile.

Observed issue: the empty state is helpful, but narrow viewport capture showed content clipping. A scoped CSS fix has been applied.

Recommended changes:

- Run mobile screenshot smoke checks on Student Dashboard, Student Timetable, Student Fees, Student Documents, and Student Course Hub.
- Prefer card layouts over tables on student mobile pages. Completed for the priority Student Dashboard, Fees, Documents, and Course Hub surfaces.
- Keep empty-state actions short and direct. Partially completed for Student Timetable.

### P2 - Destructive and risky actions need stronger context

Affected pages: Program Chair curriculum manager, shared Admin/Teacher delete modals.

Observed issue: the delete subject action is compact and easy to scan, but it is too visually similar to normal table actions for a high-impact curriculum change.

Recommended changes:

- Keep the icon, but use confirmation copy that names the subject, program, term, and downstream impact. Completed for Program Chair curriculum subject removal.
- Strengthen shared destructive-action modal context. Completed for Admin and Teacher shared delete modals.
- Add disabled/read-only state when the curriculum is locked or already used by published timetable/course delivery records.

### P2 - Empty states should link directly to repair paths

Affected page: Teacher attendance.

Observed issue: the empty state explains why no classes are available, which is good. It should also link directly to the likely repair paths.

Recommended changes:

- Add links to "My timetable", "Faculty availability/profile", and a help/escalation route for missing published classes. Completed with links to My timetable, Availability profile, and Teacher profile.
- When a teacher has no classes because of unpublished canonical sessions, say that explicitly.

### P2 - Sidebar scale

Affected portals:

- Admin
- PMC
- Admission

Observed issue: sidebars are comprehensive but long. For expert users this is acceptable; for newer users it creates orientation cost.

Recommended changes:

- Keep the existing manifest sidebars.
- Add a "Pinned / Daily work" top group per role.
- Collapse less frequent sections by default on mobile.
- Add search within long sidebars later if needed.
